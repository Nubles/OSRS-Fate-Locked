# The Resource Engine

The Resource Engine is the modal at `components/SupplyChainCalculator.tsx`. It
lets a player search for an item and see every way to acquire it, with each
source individually marked as **available** or **locked** against the current
game state. ~750 curated items, ~2,700 sources, recursive material breakdown,
favourites, category browser.

This document is the maintainer's map of how the data, the analyzer, the
generators, and the integrity tests fit together.

---

## 1. Data shape

### `ResourceSource` (`data/resourceData.ts`)

```ts
interface ResourceSource {
  type:    'DROP' | 'SHOP' | 'SPAWN' | 'SKILL' | 'MINIGAME' | 'MERCHANT' | 'QUEST'
         | 'PICKPOCKET' | 'CLUE';
  name:    string;                 // monster / shop / activity name
  regions: string[];               // 'Any', continent name, or continent child
  skills?: Record<string, number>; // e.g. { 'Slayer': 85 }
  quests?: string[];               // must match QUEST_DATA entries
  unlockId?: string;               // must be in BOSSES_LIST / MINIGAMES_LIST / …
  inputs?:  Record<string, number>;// recipe: { 'Rune Bar': 5 }
  outputYield?: number;            // items produced per operation
  notes?:   string;
  rarity?:  string;                // drop rate, e.g. '1/512' / 'Always'
}
```

### `RESOURCE_MAP`

`Record<string, ResourceSource[]>` keyed by item display name (title case, e.g.
`"Black D'hide Body"`). Hand-curated in `data/resourceData.ts`. **The keys are
the canonical item names** — every input, every category, every test
references them.

### `ENRICHED_SOURCES` (auto-generated)

`data/resourceEnrichment.ts` is **generated** (see §3) and *imported* by
`resourceData.ts`. Right after the literal `RESOURCE_MAP` declaration:

```ts
for (const [item, extra] of Object.entries(ENRICHED_SOURCES)) {
  const target = RESOURCE_MAP[item];
  if (target) target.push(...extra);
}
```

So the in-memory `RESOURCE_MAP` is curated entries + wiki-enriched entries,
merged at load. Do **not** hand-edit `resourceEnrichment.ts` — re-run the
generator.

### `RESOURCE_CATEGORIES` / `ITEM_CATEGORY`

Explicit category → `[item names]` mapping at the bottom of `resourceData.ts`,
plus a reverse lookup. Drives the category pill browser. Every item must be
in exactly one category — guarded by a test.

## 2. The analyzer (`utils/supplyChain.ts`)

```ts
buildAvailabilityContext(gameState): AvailabilityContext
analyzeSource(source, ctx, collectMissing): RouteStatus
isSourceAvailable(source, ctx): boolean
calculateSupplyChain(itemName, gameState): SupplyChainResult
isItemAvailable(itemName, gameState): boolean
isItemAvailableWithCtx(itemName, ctx): boolean
computeFullBreakdown(itemName, qty, path?): MaterialNode
flattenRawMaterials(node): { item, qty }[]
```

Key shape: `analyzeSource` is the single source of truth for "is this source
unlocked?". It powers both the detail UI (`collectMissing: true` populates
`missing: string[]`) and the boolean hot path (`collectMissing: false` short-
circuits).

`AvailabilityContext` turns the player's `gameState.unlocks.*` arrays into
`Set`s once; the inner check then uses O(1) lookups instead of repeatedly
scanning arrays. **When iterating many items, use
`isItemAvailableWithCtx` and build the context once** — the Resource Engine's
availability map does this for ~750 items per game-state change.

`computeFullBreakdown` walks the first recipe-style source (one with `inputs`)
for each item, scaling by `outputYield`, with depth (10) + cycle guards.

## 3. Generator scripts

Three one-off authoring tools live in `scripts/`. They pull from the OSRS
Wiki, apply curation, and emit TypeScript that's committed to the repo. Each
has an idempotency guard so a stray re-run fails loudly rather than corrupts
the data file.

### `scripts/buildCraftables.mjs`

- **Pulls:** Smithing, Crafting, and Magic recipes from the wiki `recipe`
  bucket.
- **Filters:** only standard metal tiers (Bronze → Rune), the d'hide/leather
  armour families, jewellery families. Skips phantom items, quest-only metals
  (Blurite, Lunar, …), and non-steel cannonballs.
- **Aliases:** `Runite Bar → Rune Bar` so generated inputs link to the
  existing app key.
- **Writes:** splices entries directly into `data/resourceData.ts` between the
  curated map and the category-grouping block, behind a `CRAFTED ITEMS
  (generated by …)` marker.
- **Re-run when:** you want to refresh smithing/crafting/jewellery coverage
  against the wiki. **Revert `data/resourceData.ts` first** — the script
  refuses to splice on top of an existing generated block.

### `scripts/buildPotions.mjs`

- **Pulls:** Herblore recipes.
- **Flattens:** unfinished-potion steps merged into `herb + secondary + vial`
  so new entries match the existing potion style.
- **Excludes:** Mastering Mixology potions (detected by `gourd vial` / MM
  herbs like `noxifer`, `golpar`, `buchu leaf`, `cicely`, `stinkhorn`,
  `endarkened`, `aldarium`), Barbarian potion mixes, quest junk.
- **Collapses:** multi-dose recipe rows (e.g. Super Antifire listed 4× by
  dose) to a single representative source.
- **Writes:** splices into `RESOURCE_MAP` and appends to the `'Potions'`
  category array.

### `scripts/buildSourceEnrichment.ts`

- **Pulls:** `storeline` (shops), `dropsline` (drops), `infobox_monster`
  (monster name + Leagues region), `infobox_shop` (shop name + location).
- **For each existing `RESOURCE_MAP` item**: adds up to 3 SHOP sources and
  up to 6 DROP sources from the wiki.
- **Curation applied:**
  - Strips wiki page anchors / sub-paths (`Lundail#Easy Diary` → `Lundail`).
  - Skips skilling "drop tables" (rocks, trees, patches) — already covered as
    SKILL sources.
  - Names drop sources from clue caskets as `CLUE` type, others `DROP`.
  - Resolves `unlockId` by matching drop-source name against
    `BOSSES_LIST` ∪ `MINIGAMES_LIST` (incl. reward-chest parentheticals like
    `Reward Chest (The Gauntlet)`). When set, realigns the region to
    `ACTIVITY_REGIONS[unlockId]`.
  - Drop region fallback: drop_json's "League region" → infobox_monster's
    `league_region` → `'Any'`.
  - Shop region: a tiny hand-curated `SHOP_REGION` map → infobox_shop's
    `[[Place]]` location parsed and mapped via `REGION_GROUPS` /
    `MISTHALIN_AREAS` → `'Any'`.
- **Self-reference guard:** because `resourceData` merges `ENRICHED_SOURCES`
  at load, the generator strips its own previous output off `RESOURCE_MAP`
  before deduping (otherwise everything looks "already present" and you get
  zero new entries).
- **Writes:** `data/resourceEnrichment.ts`, overwriting the whole file.
- **Re-run after:** adding new curated items or changing the unlock lists
  (so newly-added items get their wiki shops/drops too).

## 4. Wiki Bucket API conventions

Endpoint: `https://oldschool.runescape.wiki/api.php?action=bucket&format=json&query=…`

- The `query` is a tiny Lua expression: `bucket('table_name').select('a','b').limit(5000).run()`
- Bucket names are **lowercase / snake_case** (`dropsline`, not `Dropsline`;
  `infobox_monster`).
- Fields are exposed exactly as declared on the `Bucket:Foo` schema page; the
  implicit `page_name` field is *only* exposed on certain buckets.
- Hard cap of **5000 rows per query** — paginate with `.offset(N)` until you
  get back fewer than 5000.
- The OSRS Wiki's anti-bot blocks Node `fetch`; the generator scripts shell
  out to `curl` with a desktop User-Agent.

## 5. Integrity tests (`data/resourceConsistency.test.ts`)

The test suite is the contract. CI runs `npm test` on push, and four guards
defend the data:

1. **Categories cover RESOURCE_MAP exactly** — every item in exactly one
   category; no orphans; no duplicates.
2. **Source well-formedness** — every source has at least one region.
3. **Boss-drop regions agree with `ACTIVITY_REGIONS`** — any source with an
   `unlockId` that `ACTIVITY_REGIONS` knows about must list the matching
   region.
4. **`computeFullBreakdown` always terminates** — exercises every item to
   prove the cycle/depth guard works and the flatten output is sorted &
   deduped.

And four reference-integrity guards:

5. **Inputs resolve** — every recipe `inputs` key resolves to a `RESOURCE_MAP`
   item, `'Coins'`, or the `INTENTIONAL_INPUT_LEAVES` allowlist (see below).
6. **Unlock IDs resolve** — every `unlockId` matches an entry in one of the
   nine unlock lists.
7. **Skill names resolve** — every `skills` key is in `SKILLS_LIST`.
8. **Region tags resolve** — every `regions` entry is `'Any'`, a continent,
   a continent child, or a Misthalin area.

### `INTENTIONAL_INPUT_LEAVES`

A hard-coded allowlist near the top of the test file. These are recipe
ingredients that **are not** in `RESOURCE_MAP` but **shouldn't fail** the
inputs-resolve test — Mastering Mixology potions, Sailing-era ingredients,
quest-only intermediate steps. Update this set when:

- You add a new MM/Sailing/quest item to the map → remove it from the
  allowlist (now real).
- A new recipe references an ingredient you don't plan to model → add it.
- A typo in a recipe input pretends to be an allowlist entry → **don't add
  it**, fix the typo. (The test exists to make typos noisy.)

## 6. Adding a curated item — the workflow

1. **Add to `RESOURCE_MAP`** in `data/resourceData.ts`. Use the canonical
   title-case name. Every source needs at least `type`, `name`, `regions`.
2. **Categorise it** in `RESOURCE_CATEGORIES`. Pick the closest existing
   category; create a new one only if the item is part of a distinct family.
3. **Make sure inputs link.** Any `inputs` key should already exist as a
   `RESOURCE_MAP` item — otherwise it dead-ends as a raw leaf in the
   breakdown UI. If you genuinely intend it as a leaf, add to
   `INTENTIONAL_INPUT_LEAVES`.
4. **(Optional) Re-run enrichment** if the new item has shop/drop sources:
   `npx tsx scripts/buildSourceEnrichment.ts`.
5. **Run the suite:** `npx tsc --noEmit && npx vitest run`. The integrity
   tests will tell you exactly what's broken.

## 7. Region & unlock conventions

- **`REGION_GROUPS`** (`data/items.ts`) is the continent → child-areas map.
  Misthalin's children live in `MISTHALIN_AREAS` separately for legacy
  reasons; both are valid `regions` tags.
- **`ACTIVITY_REGIONS`** (`data/activityRegions.ts`) is the single source of
  truth for "which continent does this boss/minigame live in?". The God Wars
  Dungeon is `Fremennik` per this file; DT2 bosses are spread across
  Fremennik/Morytania/Varlamore; the test suite enforces consistency.
- A drop source with `unlockId: 'Vorkath'` should have
  `regions: ['Fremennik']` (Vorkath's `ACTIVITY_REGIONS` entry). The
  generator does this automatically when it resolves an unlock.

## 8. Image lookups (`services/WikiService.ts`)

- Item names in the app are title case but wiki articles are sentence case
  (`Barronite Shards` vs `Barronite shards`). The service queries **both**
  the title-cased title and a sentence-cased variant in the same batch, and
  falls back to the variant when the title-cased page has no image. This
  fixes images app-wide without breaking proper-noun pages (bosses).
- `WIKI_OVERRIDES` (`data/assets.ts`) is the escape hatch for names that
  hit a disambiguation page (e.g. `Gnome Village` →
  `Tree_Gnome_Village`). Store the **raw** wiki page name — do not
  URL-encode; `URLSearchParams` does that for you.
- `CACHE_KEY = 'fate_uim_wiki_cache_v3'`. Bump the version suffix whenever
  the resolution logic changes so stale null cache entries are dropped.

## 9. Known limitations / deferred work

- **Mastering Mixology potions** are excluded by the potion generator and the
  ~half-dozen MM-ingredient items are in `INTENTIONAL_INPUT_LEAVES`. Adding
  them needs a `Mastering Mixology` minigame unlock tag so the lock analysis
  stays correct.
- **Sailing items** (`Caviar`, `Yellow Fin`, `Marlin Scales`, `Pillar Coral`,
  `Haddock Eye`, `Pharmakos Berries`) are likewise on the allowlist. The
  Sailing skill itself isn't modelled yet.
- **GE prices** integration was deliberately deferred (one of the original
  PLAN.md features). `services/PriceService.ts` exists.
- **~1,158 enriched drops still tagged `'Any'`** — mostly multi-region
  monsters (Bronze/Iron/Steel/Mithril dragons, etc.) the wiki doesn't pin to
  a single Leagues region. Improving these further needs a hand-curated
  monster → region map.
- **Quest-requirement audit** — `quests` tags are accurate on curated
  sources but absent on enriched ones.

## 10. Common commands

```sh
# Type-check
npx tsc --noEmit

# Run the test suite (91+ tests; integrity guards are in here)
npx vitest run

# Build (chunks should split cleanly; no >500 kB warning)
npx vite build

# Refresh wiki-sourced enrichment after changing RESOURCE_MAP
npx tsx scripts/buildSourceEnrichment.ts

# Refresh smithed-item / potion coverage (revert the data file first!)
git checkout data/resourceData.ts
node scripts/buildCraftables.mjs
node scripts/buildPotions.mjs
npx tsx scripts/buildSourceEnrichment.ts
```
